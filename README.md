## Что это за проект

Здесь описан простой API для совместной работы с доской: получить доску, создать, изменить или удалить стикер, добавить комментарий и закрыть его.

Главная идея проекта — показать, как контракт API можно подготовить **до разработки серверной части**. По готовому контракту уже можно:

- читать документацию OpenAPI в **ReDoc**;
- отправлять запросы через **Swagger UI**;
- имитировать работу API через **Prism**;
- отдельно описывать события через **AsyncAPI**.

Проект запускается на **macOS, Windows и Linux**. Docker, WSL, Python и отдельный брокер сообщений не нужны.

## Что нужно установить

Для запуска достаточно трёх вещей.

### 1. Git

Git нужен, чтобы скачать проект с GitHub и при необходимости получать обновления.

Скачать Git: https://git-scm.com/downloads

После установки откройте Терминал на macOS/Linux или PowerShell/Terminal на Windows и проверьте:

```bash
git --version
```

Если команда выводит номер версии, Git установлен.

### 2. Node.js

Проект использует Node.js версии **20.19 или новее, но ниже 25**. Рекомендуемый вариант — актуальная версия **Node.js 22 LTS**.

Скачать Node.js: https://nodejs.org/

`npm` устанавливается вместе с Node.js, отдельно устанавливать его не нужно.

Проверьте установку:

```bash
node --version
npm --version
```

Обе команды должны вывести номера версий.

### 3. VS Code — необязательно

VS Code нужен только если вы хотите открыть и изучать файлы проекта. Для запуска проекта он не требуется.

Скачать VS Code: https://code.visualstudio.com/

## Как скачать и запустить проект впервые

### Шаг 1. Откройте терминал

Можно использовать:

- **macOS** — приложение Terminal;
- **Windows** — PowerShell, Windows Terminal или терминал VS Code;
- **Linux** — любой терминал.

### Шаг 2. Скачайте проект с GitHub

Выполните:

```bash
git clone https://github.com/skalinina/getanalyst-contract-first.git
```

Git создаст на компьютере папку `getanalyst-contract-first` со всеми файлами проекта.

Перейдите в неё:

```bash
cd getanalyst-contract-first
```

Все следующие команды нужно выполнять из этой папки.

### Шаг 3. Установите зависимости

Выполните:

```bash
npm install
```

Команда скачает библиотеки, которые нужны проекту. Они появятся в папке `node_modules`.

`npm install` обычно требуется только при первом запуске или после изменения зависимостей проекта.

### Шаг 4. Запустите проект

Выполните:

```bash
npm run demo
```

Сначала проект соберёт документацию, затем запустит локальные сервисы.

После запуска откройте в браузере:

| Что | Адрес | Для чего |
|---|---|---|
| **ReDoc** | `http://localhost:8080` | Документация OpenAPI и вкладка AsyncAPI |
| **Swagger UI** | `http://localhost:8081` | Просмотр и отправка запросов к API, вкладка AsyncAPI |
| **Prism** | `http://localhost:4010` | Имитация API по OpenAPI-контракту |

Чтобы остановить проект, вернитесь в терминал и нажмите `Ctrl + C`.

## Как запустить проект в следующий раз

Снова устанавливать зависимости не нужно. Откройте терминал, перейдите в папку проекта и выполните:

```bash
cd getanalyst-contract-first
npm run demo
```

Если папка находится не в текущем каталоге, сначала перейдите в место, где вы её сохранили.

## Что входит в контракт

### OpenAPI

В спецификации есть несколько простых операций:

```text
GET    /boards/{boardId}
POST   /boards/{boardId}/sticky-notes
PATCH  /boards/{boardId}/sticky-notes/{stickyNoteId}
DELETE /boards/{boardId}/sticky-notes/{stickyNoteId}
POST   /boards/{boardId}/comments
POST   /boards/{boardId}/comments/{commentId}/resolve
```

Для них описаны:

- входные и выходные данные;
- примеры запросов и ответов;
- Bearer-аутентификация;
- ответы `400`, `401`, `403`, `404`, `409`;
- правила доступа в `description` операций.

### AsyncAPI

Асинхронная часть описывает событие `BoardChanged`, которое публикуется после изменения доски.

Например:

```text
STICKY_NOTE_CREATED
STICKY_NOTE_UPDATED
STICKY_NOTE_DELETED
COMMENT_CREATED
COMMENT_RESOLVED
```

Такое событие может обработать другой сервис, например сервис уведомлений.

## Как устроен проект

```text
openapi/                 OpenAPI-контракт
asyncapi/                AsyncAPI-контракт, каналы и сообщения
schemas/                 Структуры данных и ограничения
examples/                Примеры запросов, ответов и событий
scripts/                 Скрипты сборки и запуска
.vscode/                 Рекомендованные расширения VS Code
```

Схемы и примеры разделены специально:

```text
schemas/   → какие данные допустимы
examples/  → как выглядят конкретные данные
```

Например, операция отдельно ссылается на схему и на пример:

```yaml
schema:
  $ref: ../schemas/openapi/sticky-note.yaml
examples:
  created:
    $ref: ../examples/openapi/sticky-note-created-response.yaml
```

## Как переходить по `$ref` в VS Code

Для работы со ссылками `$ref` рекомендуется расширение **Redocly OpenAPI**.

В проекте уже есть файл `.vscode/extensions.json`, поэтому VS Code может сам предложить установить расширение.

После установки можно использовать:

- `Cmd + Click` на macOS;
- `Ctrl + Click` на Windows/Linux;
- `F12` — перейти к определению;
- **Peek Definition** — посмотреть определение, не закрывая текущий файл.

## Авторизация в Swagger UI

Нажмите **Authorize** и введите любой тестовый токен, например:

```text
demo-token
```

Swagger UI отправит его как Bearer token.

Prism не проверяет настоящий JWT и права пользователя. Он только имитирует ответы, описанные в контракте. Это не настоящая серверная часть приложения.

## Важное про Prism

Prism не хранит состояние между запросами.

Например, если создать стикер через `POST`, он не сохранится и не появится при следующем `GET`. Для этого проекта такое поведение ожидаемо.

Prism нужен, чтобы проверить контракт и попробовать запросы ещё до появления настоящей серверной реализации.

## Если что-то не запускается

Сначала проверьте, что вы находитесь в папке проекта и что Git, Node.js и npm доступны:

```bash
git --version
node --version
npm --version
```

Если после скачивания проекта команда `npm run demo` сообщает, что не найдена какая-либо зависимость, выполните ещё раз:

```bash
npm install
```

Если один из адресов `localhost` не открывается, проверьте терминал: проект должен продолжать работать, а окно терминала не должно быть закрыто.
